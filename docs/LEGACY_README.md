## 启动

双击 `Start-FlySnake.cmd`，或在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -u -m flysnake.server --port 8771 --storage-root runtime/stronger-feedback-v6
```

当前更新版地址为 http://127.0.0.1:8771 。启动器读取 `runtime/active-server.json` 选择当前服务与记忆目录。初次加载要等待真实连接组进入内存。默认运行，后续启动会按 `runs/latest_memory.json` 指针恢复已提交的神经记忆，保留长期 u/w 状态并开始新棋局。需要只加载暂停时加 `--paused`；`--fresh` 表示跳过普通的历史记忆恢复，不删除原文件。若存在待提交反馈，程序仍会先完成下文的恢复流程，`--fresh` 不绕过该事务。

下文持久化路径均相对于 `--storage-root`；当前为 `runtime/stronger-feedback-v6/`。更新时已校验复制旧实例的长期记忆，旧的项目根目录 `runs/` 保留作为历史记录。网页、神经代码和连接组数据仍使用同一项目。

## 安装与准备

项目需要 Python 3.12；所有第三方依赖仅安装在项目 `.venv`。神经编译器使用 Python 包内的 Zig，不需要全局安装 Visual Studio 或交易软件。

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.\.venv\Scripts\python.exe scripts\prepare_brain.py
```

数据准备使用 Janelia 官方公开数据，并验证来源文件及编译数组。原始数据约 1.1 GB，规范化与缓存需要额外空间。数据在 `data/malecns_v1/`，程序不会读取交易账号或密钥。首次编译、加载和神经运行速度取决于电脑可用内存与 CPU。

## 严格控制约束

- 神经模型在独立进程运行，只接收感官 RGB 和明确的奖惩刺激；它不接收棋盘坐标、食物方向或危险动作标签。
- 固定读出比较左 DNp20、双侧 DNpe017 平均活动、右 DNp20 的新脉冲率。左右转通道的差距不超过较强一侧的 20% 时输出直行；超过 20% 才采用较强的转向。它是公开的工程脑机接口，不是已证明的自然贪吃蛇功能。
- 一份新的有效动作凭据只能推进一格；无输出或持续平局时，保持棋局、步数和食物不变，交付完整 200 ms 惩罚并持久化记忆后继续神经计算，不因此自动暂停，也不生成替代动作。旧凭据、错误观察和重复动作均拒收。
- 游戏不按 UI 刷新率自行移动，不过滤致死方向。
- 蛇头撞墙或进入未腾空的身体格都会死亡并触发惩罚；正常移动允许进入本步已腾空的尾格。
- 吃食或死亡发生后先交付完整 200 ms 神经刺激和可塑更新，再生成新食物或重开棋局。短时状态按统一协议复位，长期 u/w 状态保留。
- 左转/直行/右转由神经输出决定；暂停、新棋局和保存是实验者控制，不是蛇的方向操作。手动暂停仍会停止继续尝试，神经进程或协议异常仍会停机并显示错误。

## 页面与证据

页面展示棋盘、实际感官画面、三个输出通道、真实反馈与记忆统计。最近奖惩明确区分食物奖励、死亡惩罚和无有效输出惩罚。无有效输出惩罚后继续尝试；加载失败、手动暂停和执行错误也会明确显示，不填充虚假演示数据。

感官画面展示整个棋盘，棋盘位置和朝向固定：珊瑚红蛇头在棋盘中移动，蓝色食物被吃到前始终占据相同像素位置，绿色身体（RGB 70,160,110）随蛇移动，黑色外圈墙面保持固定。画面不跟随蛇头平移或转向。默认 12×12 棋盘居中绘入 320×180 RGB，每格为 12×12 像素，外侧是一格厚的黑色墙。这些颜色由后端直接绘入神经输入 RGB，前端只复制已校验的原图。视觉版本为 `fixed-world-distinct-body-v4`。

状态接口在同一快照中返回棋盘、感官 PNG 及其来源步骤；网页先解码并校验 RGB 哈希，再在同一次画面刷新中呈现棋盘与感官图。奖惩期间明确标注动作前画面，新局预热显示真正的 RGB128 中性灰帧。带版本的图片 URL 只返回该版本，已淘汰版本返回 410，未知版本返回 404。旧接口的网页兼容流程也必须先配对哈希，不会用下一步图片替代当前帧。

每次运行的日志位于 `runs/YYYYMMDD-HHMMSS-<会话UUID前8位>/events.jsonl`。其中记录动作前图像哈希、细胞 ID、本次脉冲、分数、神经时间、动作凭据、游戏结算和实际反馈，以及 `feedback_scheduled`、`feedback_committed` 和恢复事件。图像哈希与完整神经检查点支持核查，但结构化记录本身不等于外部密码学证明。

## 记忆保存与中断恢复

奖励与惩罚的刺激强度均为 30（模型等效值），从原来的 20 提高到 1.5 倍，交付时长仍为 200 ms。页面“最近奖惩”显示实际回执中的强度；刺激增强不代表学习效果按同一倍数增强。

自动保存默认开启：模型有新活动且距上次成功保存满 60 秒后，在当前神经计算或完整奖惩事务结束时保存。手动暂停会保存最新状态；吃食、死亡和无有效输出的反馈完成后也保存。暂停期间状态不变，不会反复写入相同记忆。页面显示最近成功保存时间，“保存记忆”按钮仍可立即额外保存。

已经运行的旧版进程可由 `scripts/autosave_current_session.py` 通过现有保存接口启用相同自动保存条件，避免中断当前大脑；它不控制移动。启动器会识别这种情况。辅助进程只在本地 `127.0.0.1:8766/status` 提供自动保存状态，页面优先使用主程序内置状态；检测到新版内置自动保存后，辅助进程自动退出。

每次保存创建独立的检查点代次 `runs/checkpoints/brain-<纳秒时间戳>/`，包含 `brain.npz`、`brain.npz.adapter.json` 和记录文件哈希的 `commit.json`。已有代次保持不变。检查点及元数据写完后，程序原子替换 `runs/latest_memory.json`，使其指向本次已提交的代次；恢复时先核对路径和文件哈希。

奖惩使用 `runs/pending_feedback.json` 记录待提交事务。实际刺激前，程序保存一份反馈前的独立检查点、固定的动作前画面 `feedback.png` 及其哈希，并写入带会话标识的事务 ID。完整反馈后再保存新代次，以 `latest_memory.json` 中的 `completed_event_id` 提交该事务，随后清除待提交记录。

若进程在反馈期间中断，重启时会检查待提交记录：最新代次已经包含该事务 ID，就恢复已提交状态并跳过重复刺激；尚未提交，就从反馈前检查点及已校验画面重放完整反馈，再提交新的检查点。恢复完成后按统一协议复位短时状态、执行中性预热，保留长期可塑状态进入新棋局。原棋局的位置、分数和逐帧进度不作为续玩状态恢复。

这些文件共同保存实验记忆与反馈恢复依据。不要删除检查点、指针或待提交记录来“修复表现”；保存或恢复校验失败会停止游戏。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

自动测试中的确定性脉冲是仅用于测试的 fixture，生产运行没有模拟脑/假脉冲路径。游戏与控制约束通过不等于模型已经学会游戏。需要冻结学习、无外部奖惩、打乱配对和记忆重置等对照，才能判断成绩是否因学习提高。
